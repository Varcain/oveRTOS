# FreeRTOS — zero-heap mode

Cross-binding benchmark report measured on **STM32F746G-DISCOVERY** (Cortex-M7 @ 216 MHz) running FreeRTOS with `CONFIG_OVE_ZERO_HEAP=y` (`_init()` / `_deinit()` API, caller-supplied static storage, heap locked at `ove_run()`).

Compared to [FreeRTOS heap mode](freertos-heap.md), the `*_create_destroy` and `*_memory` cases are gated out — the create/destroy API isn't generated under zero-heap.  Per-call hot paths (lock/unlock, take/give, send/receive, signal/wait) should match heap-mode within measurement noise.

For methodology, statistical conventions, and how to reproduce, see the [benchmarks overview](index.md).

> *Generated by `scripts/bench_compare.py`. Trimmed-mean (top 1% dropped) when available, else avg. Delta column is `(binding − C) / C` — values within ±10.0% are within typical measurement noise.*

**Note on `native_*` rows in the main table.** `bench_native_freertos.c` is C code calling raw FreeRTOS APIs (`xSemaphoreTake`, `xQueueSend`, `xTaskCreateStatic`), compiled identically into every binary. The CPP/RUST/ZIG columns for those rows are *the same C code measured in three different processes* — they reflect cross-run scheduler noise, not any binding-level difference. The meaningful number is the **within-run wrapper-vs-native delta** in the dedicated section below.
